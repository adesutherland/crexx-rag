## Canonical Plan Contract

`ragcanonical.crexx` is the single owner of the byte-stable non-secret config,
profile, and provider-route/privacy projections used by initialization and
planning. It delegates SHA-256 to installed `rxhash`.

`ragplanning.crexx` emits one bounded `crexx-rag.plan/1` JSON object and its
lowercase SHA-256. The fixed member order binds:

- the apply operation and a strictly shaped registered action;
- opaque library id and published generation;
- config snapshot id, registered config id, and effective config hash;
- registered profile id and profile hash;
- a hash of visible current source/revision envelope and metadata fingerprints;
- a hash of provider role, route-class, and privacy-policy declarations;
- a hash of non-terminal non-zero job reservations;
- the required `ingest` or `curate` capability; and
- SQLite-observed creation time plus an exact one-hour expiry.

The three planning commands are `ingest plan --source-set ID`, option-free
`improve plan`, and `proposal plan --input-digest SHA256`. Config, profile,
source-set, and proposal input identities are data, never executable module
paths. The shared facade returns the canonical bytes and digest in a typed
record; it does not save a file.

## Hostile Apply Boundary

Apply checks the operation-specific capability before inspecting plan content.
It then verifies the supplied reviewed digest, parses the JSON once, requires
the exact bounded object shapes and scalar types, reconstructs the one canonical
encoding, and requires byte equality. A fresh pinned read transaction
recomputes generation, config/profile identity and hashes, current source
fingerprints, provider privacy routes, reservations, and current time. Any
state change or expiry returns stable conflict exit 6 and requires re-planning;
malformed, digest-mismatched, or noncanonical content returns integrity exit 7.

A fully valid plan reaches `state=revalidated` but returns stable unavailable
exit 8 with `enqueued=false`. This is deliberate: P2-10 proves the safe boundary
without implementing the Phase-3 ingestion or Phase-4 improvement/proposal job
paths.

## Focused Proof

CTest `p2_10_plan_revalidation` compiles 18 application/configuration/scenario
modules with and without optimization and runs both VMs. Every cell:

- creates all three canonical plan forms and verifies their typed contents;
- proves planning and valid apply revalidation leave database, manifest, WAL,
  and shared-memory fingerprints unchanged;
- denies planning without `plan` and apply without the operation capability;
- denies a mismatched reviewed digest and valid-but-noncanonical JSON;
- independently tampers and re-hashes config, profile, source, provider-route,
  and reservation bindings, proving each is recomputed rather than trusted;
- re-encodes an expired but otherwise canonical plan and rejects it;
- inserts a competing reservation and publishes a new generation, proving both
  live state changes force re-planning;
- denies unregistered source sets and malformed proposal digests; and
- accepts no enqueue and makes zero provider calls.

CMake hashes every source input before and after the four cells. The final
isolated focused run passed in 39.70 seconds with 246,288 KiB maximum RSS.
