# P2-07 Command And Result Contracts

Status date: 2026-08-23. `P2-07` is accepted. This evidence freezes Level-G
command parsing, stable exit identities, and bounded human/JSON/NDJSON result
contracts. It does not dispatch an operation, replace the current native CLI,
or accept the P2-08 lifecycle/provider/profile commands as implemented.

## Parser Contract

`ragcommand.crexx` is Level-G application code. It freezes the approved target
vocabulary at 40 operations: `doctor` plus every noun/verb combination listed
for library, provider, profile, source, ingest, job, worker, query, improve,
proposal, review, and MCP serving in the approved specification.

Global `--library`, `--config`, `--profile`, `--format`, and repeated/comma-
separated `--access` options must precede the noun. Format is exactly `human`,
`json`, or `ndjson`; registered ids use the same safe id grammar as P2-02; and
access is limited to `read`, `plan`, `control`, `ingest`, `curate`, `diagnose`,
or `admin`. Access values are ordered and deduplicated, defaulting to `read`.
Commands that operate on a library require an explicit target, except restore,
whose fresh output target belongs to P2-08 validation.

Post-operation options retain name, value, and flag identity. Positionals are
exact argv values, and `--` makes every remainder positional, including text
beginning with `--`. No command or source text is passed through a shell. Input
is bounded to 128 arguments; names and values have explicit limits. Unknown
global options and operations are rejected rather than forwarded to arbitrary
modules or tables.

## Stable Results

Exit codes 0 through 10 have fixed names: success, operation-failed, usage,
configuration, access-denied, not-found, conflict, integrity, unavailable,
cancelled, and internal. Code 0 requires result status `ok`; every nonzero code
requires `error`.

`ragcommandresult` contains bounded typed records. Each field is one of string,
canonical integer, boolean, or null; field names are unique and safe. Rendering
rejects more than 100 records or 100 fields per record, invalid typed values,
unknown field kinds, exit/status mismatch, or an unknown output format.

The machine schema is `crexx-rag.command-result/1`. JSON is one object containing
metadata and records. NDJSON is a reconstructable result header followed by one
line per indexed record, each repeating schema and operation identity. Human
output begins with the same success/error, operation, and stable exit name and
then prints one record per line; embedded CR/LF/tab values are made single-line
for terminal safety.

## Focused Proof

CTest `p2_07_command_contract` compiles `ragmodel`, `ragcommand`, and the
consumer with and without optimization and runs both VMs. Every cell:

- parses all 40 frozen operations;
- proves global inline/separate values, repeated/deduplicated access, command
  values/flags, exact positional `--` behavior, and defaults;
- rejects unknown globals/operations, invalid formats/access/ids, duplicate
  globals, missing library targets, late globals, and misplaced separators;
- asserts all 11 exit names and unknown-code behavior;
- renders Unicode and embedded-newline data to all three formats;
- parses JSON and every NDJSON line with installed `rxjson` and compares typed
  semantic fields; and
- rejects status/exit disagreement, noncanonical integer fields, duplicates,
  unbounded record counts, and unsupported formats.

CMake hashes the model, command module, and consumer before and after all four
cells. The inputs remain identical and the runtime reports zero library writes
and zero provider calls. The final isolated run passed in 3.81 seconds with
201,040 KiB maximum RSS; the same test passed in 5.50 seconds in the full
parallel run.

## Full Validation

The per-item gate uses the same fresh installed CREXX package, Debug build, and
a new Release build directory:

```text
cmake -S . -B <debug> -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_PREFIX_PATH=<scratch-crexx> -DCREXX_DIR=<scratch-crexx>/lib/cmake/CREXX
cmake --build <debug> --parallel 10
ctest --test-dir <debug> --parallel 10 --output-on-failure
cmake -S . -B <release> -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH=<scratch-crexx> -DCREXX_DIR=<scratch-crexx>/lib/cmake/CREXX
cmake --build <release> --parallel 10
git diff --check
```

Debug configure/build succeeded and the full suite passed 66/66 in 91.19
seconds. A fresh Release configure/build in a new directory succeeded.
`git diff --check`, the donation-document audit, and the language-level audit
passed. No generated application artifact was written into the source tree.

## Remaining Limits

- Parsing and rendering are implemented; operation-specific option validation
  and lifecycle dispatch begin in P2-08.
- The current native executable remains the oracle and shipped CLI. P2-07 does
  not claim that its target command vocabulary is installed as an executable.
- ADDRESS RAG and MCP transport adapters remain Phase 6; they will consume the
  same typed request/result contract rather than reparse business behavior.
- Exact downstream Linux confirmation remains later QA after further material
  current-host progress.

`P2-08` is next and pending. No later item is active or implied complete by this
result.
