## Implemented Boundary

`crexx/application/ragcompat.crexx` is a maintained Level-G module. It exposes:

- read-only version-1 bundle inspection;
- a typed dry-run conversion report containing source counts, imported and
  quarantined counts, warnings, and explicit source/target write state; and
- side-by-side import into a required new schema-v2 bundle followed by
  generation publication, manifest publication, and full store verification.

The source manifest must identify `crexx-rag-library` format version 1 and
`library.sqlite`. Inspection validates the required version-1 table/column
surface before counting rows. Both inspection and import open the source
read-only; import attaches it through SQLite's read-only immutable URI mode.
The target must not exist, so conversion cannot overwrite or dual-write a
library. Failure removes only the newly created incomplete target.

## Conversion Policy

The target starts as schema version 2, generation 1, and publishes the import
as generation 2. The deterministic mapping is:

- documents become sources, external-reference artifacts, revision text, and
  revisions;
- chunks become immutable chunk content, revision occurrences, normalization
  maps, and the FTS projection;
- entities become concepts; and
- shape-valid float32 embeddings become embedding profiles, embeddings, and
  revision-chunk links.

Version-1 content hashes and other legacy identities are retained as explicit
`legacy-v1` provenance strings; the importer does not relabel them as SHA-256.
Every document and entity metadata record is retained as a pending review.
Edges are retained as `legacy-unverified-claim` reviews rather than accepted
claims. Candidate mentions/adjudications and work/attempt history are retained
as reviews; legacy work is not resumed. Embeddings whose byte length does not
equal `dimension * 4` are excluded from the embedding tables and quarantined as
reviews.

This is deliberately evidence-preserving rather than semantic promotion. P2-06
repository APIs may expose imported records, but no later item may silently
upgrade a quarantined decision or legacy digest.

## Focused Proof

CTest target `p2_04_v1_compatibility` compiles `ragschema`, `ragstore`,
`ragcompat`, and the behavioral consumer with and without optimization, then
runs both `rxvme` and `rxbvm`.

All four cells create an exact representative version-1 schema containing two
documents, three chunks, two entities, one edge, two embeddings, one candidate
mention, one adjudication, one work item, and one attempt. Each cell proves:

- the dry-run reports the expected counts, imports one valid embedding, and
  predicts ten quarantined review records;
- dry-run creates no target;
- import publishes a fresh schema-v2 generation with 2 sources, 3 chunks,
  2 concepts, 0 accepted claims, 1 valid embedding, and 10 reviews;
- the imported store passes full integrity/foreign-key/manifest verification;
- a second import cannot overwrite the existing target; and
- a version-2 manifest presented as conversion input is rejected without a
  target.

Before and after dry-run, successful import, and rejected conversion, CMake
compares the complete recursive source bundle by relative filename, size,
mtime, and SHA-256. Every comparison is identical. This directly proves zero
source writes across the four runtime/compiler cells.

The isolated focused CTest passed in 8.41 seconds with 221,840 KiB maximum RSS.
The focused test also passed in the full parallel Debug run in 15.00 seconds.

## Full Validation

The current-host validation used a scratch build and explicit scratch-installed
CREXX package discovery:

```text
cmake -S . -B <debug> -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_PREFIX_PATH=<scratch-crexx> -DCREXX_DIR=<scratch-crexx>/lib/cmake/CREXX
cmake --build <debug> --parallel 10
ctest --test-dir <debug> --parallel 10 --output-on-failure
cmake -S . -B <release> -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH=<scratch-crexx> -DCREXX_DIR=<scratch-crexx>/lib/cmake/CREXX
cmake --build <release> --parallel 10
git diff --check
```

Debug configure/build succeeded and the full suite passed 63/63 in 88.73
seconds. Fresh Release configure/build succeeded. `git diff --check` passed.
No generated application artifacts were written into the source tree.

## Remaining Limits

- P2-04 is a compiled application-module boundary; P2-07/P2-08 own the public
  command and result surfaces.
- The importer retains external source references and normalized text assembled
  from version-1 chunks; it does not claim to reconstruct an absent raw source
  artifact.
- Version-1 vector-index state and a FAISS sidecar are not promoted. Valid
  embedding rows are imported, while P2-05 owns immutable matching sidecars and
  P2-06 owns repository access to them.
- Backup, restore, and crash-ordered sidecar publication remain P2-05.
- P2-06 owns paged repositories and complete lifecycle/orphan invariants.
- Exact downstream Linux confirmation remains a later QA activity after
  material current-host progress; it is not a P2-05 entry blocker.

`P2-05` is next and pending. No later Phase-2 item is active or implied complete
by this result.
