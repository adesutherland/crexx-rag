# P2-01 Level G Application Contracts

Status date: 2026-08-04. `P2-01` is accepted. This evidence covers the
application module layout and public object contracts only; it does not claim a
schema, persistence implementation, configuration loader, command surface, or
provider operation.

## Implemented Boundary

The new `crexx/application/` package contains:

- `ragmodel.crexx`: nominal errors, operation results, request options, plans,
  traces, paths, timelines, and review pages;
- `ragevidence.crexx`: citations, passages, retrieval scores, independently
  addressable claim support, directional accepted claims, ambiguity, graph
  leads, gaps, trace, guidance, and optional generated answers;
- `ragjob.crexx`: full public job status, event paging, and pause/resume/cancel
  interface;
- `raglibrary.crexx`: library status, search results, the `raglibrary`
  interface, and the `raglibraryfactory` open contract; and
- `tests/p2_01_contract_consumer.crexx`: a compiled in-memory implementation
  and consumer of the complete public method vocabulary.

All five cREXX sources use `options levelg`. The product package imports no
`rxrag`, native-v1 facade, incubation module, SQLite plugin, HTTP module, or
provider module. No pass-through language-level wrapper or Level-B exception
was required.

The public flow is factory-led so later configuration and SQLite work can
supply a concrete implementation without changing callers:

```text
library = library_factory.open(path, access, config_id)
status = library.status()
packet = library.evidence(question, request_options)
job = library.apply(plan, expected_digest)
```

The contract includes every operation listed by the approved architecture:
status, ingest/improvement/proposal planning, apply, search, evidence, answer,
trace, path, timeline, review, close, job status/events/control, and evidence
passages/claims/leads/trace.

## Focused Proof

CTest `p2_01_application_contract` compiles `ragmodel`, `ragevidence`,
`ragjob`, `raglibrary`, and the consumer in optimized and non-optimized modes.
It then runs the consumer on both VMs. All four cells passed:

```text
noopt-rxvme  P2_01_OK
noopt-rxbvm  P2_01_OK
opt-rxvme    P2_01_OK
opt-rxbvm    P2_01_OK
```

The runtime assertions cover factory/open syntax, library status and required
capabilities, all plan methods, interface-valued job return, status/events and
control, typed passage pages, temporal/source/retrieval metadata, directional
claim support and confidence breakdown, ambiguity, graph-lead limitations,
gaps, trace, answer guidance, optional answer, path, timeline, review, and
close. The final focused audit-and-contract repeat passed in 15.59 seconds.
