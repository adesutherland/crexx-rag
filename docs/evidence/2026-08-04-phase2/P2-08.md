# P2-08 Foundation Command Facade

Status date: 2026-08-23. `P2-08` is accepted. This evidence covers the first
shared Level-G operation dispatcher for `doctor`, the seven library lifecycle
commands, provider status/configuration testing, and profile validation. It
does not install a replacement CLI, contact a provider, resolve a credential,
or authorize later-phase operations.

## Shared Dispatch

`ragfoundation.crexx` consumes the `ragcommandrequest` and produces only the
bounded `ragcommandresult` established by P2-07. It implements exactly:

- `doctor`;
- `library init`, `status`, `verify`, `backup`, `restore`, and `migrate`;
- `provider status` and `provider test`; and
- `profile validate`.

All other frozen vocabulary returns stable `unavailable` exit 8. Operation
options are closed per command, duplicated values and positionals are denied,
and the access check precedes each mutation. `read` admits status and profile or
provider inspection, `diagnose` admits integrity/provider tests, and `admin`
admits lifecycle writes and subsumes the narrower checks.

## Library Lifecycle

Initialization resolves only registered configuration/profile ids. It builds a
deterministic canonical non-secret projection, hashes the complete effective
projection and profile with installed `rxhash.sha256`, and persists the
snapshot through `initragstore`. Symbolic `env:` references may identify how an
operator supplies a secret, but no secret value is loaded or retained.

Status and verification use strict read-only opens. Verification combines the
P2-03 store/manifest checks with the P2-06 repository invariant verifier on a
pinned snapshot. Migration uses the ordered P2-03 migration path and is
idempotent when already current. Backup and restore delegate to the P2-05
generation-pinned, immutable-sidecar, fresh-target implementation and return
typed generation/page/publication facts.

## Diagnostics And Providers

`doctor` reports four required facilities as loaded because the compiled
facade has successfully resolved SQLite, JSON, SHA-256, and binary-file
boundaries. It separately reports registry validity, provider declarations as
`configured-not-probed`, and optional library integrity. A malformed library is
therefore an integrity failure rather than an unavailable optional provider.

Phase 2 does not authorize a new hosted request. `provider status` reports only
non-secret declarations. `provider test` validates a selected local
configuration and explicitly records `outbound_attempted=false` and
`credential_resolved=false`; it does not claim reachability. A hosted provider
returns stable unavailable status with `authorization-required`, also with zero
outbound and zero credential resolution. Live local/hosted canaries and
provider-lifetime qualification remain separate later work.

## Focused Proof

CTest `p2_08_foundation_facade` compiles 15 application/configuration modules
and the consumer with and without optimization, then runs both VMs. Every cell:

- denies init before filesystem mutation when `admin` is absent;
- initializes once and rejects overwrite;
- reads status and verifies store, manifest, and repository invariants without
  changing database or manifest hashes;
- migrates the current schema twice successfully;
- runs library-aware `doctor` and validates a registered profile;
- reports all three providers without exposing the symbolic credential name in
  rendered output;
- exercises a local configuration-only provider test and denies the hosted
  canary with zero calls and credential resolutions;
- creates a generation-pinned backup without changing the source bundle,
  restores into a fresh folder, and verifies the restore; and
- rejects unknown options and a later-phase operation.

CMake hashes every source input before and after the four cells and verifies
that all library, backup, and restored bundles contain both database and
manifest. The isolated focused run passed in 31.48 seconds with 239,632 KiB
maximum RSS.

## Full Validation

The per-item gate uses the scratch installed package, the continuing Debug
tree, and a newly configured Release tree:

```text
cmake -S . -B <debug> -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_PREFIX_PATH=<scratch-crexx> -DCREXX_DIR=<scratch-crexx>/lib/cmake/CREXX
cmake --build <debug> --parallel 10
ctest --test-dir <debug> --parallel 10 --output-on-failure
cmake -S . -B <release> -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH=<scratch-crexx> -DCREXX_DIR=<scratch-crexx>/lib/cmake/CREXX
cmake --build <release> --parallel 10
git diff --check
```

Debug configure/build succeeded and the full suite passed 67/67 in 95.59
seconds. A fresh
Release configure/build succeeded. `git diff --check`, the donation-document
audit, and the language-level audit passed. No generated application artifact
was written into the source tree.
