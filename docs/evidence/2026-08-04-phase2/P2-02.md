# P2-02 Registered Configuration And Profiles

Status date: 2026-08-04. `P2-02` is accepted. This evidence covers typed,
operator-registered configuration and profile construction only; it does not
claim provider execution, source reads, persistence, or a production job
snapshot.

## Implemented Boundary

All maintained implementation and consumer sources use `options levelg`:

- `ragconfig.crexx` defines typed source sets, providers, symbolic secret
  references, role routing, budgets, worker scope, schedules, validation, and a
  non-secret selection projection;
- `ragprofile.crexx` defines independent typed vocabulary, relationships and
  inverse references, aliases, chunk policy, ranking weights, prompt
  identities, validators, and validation;
- `ragregistry.crexx` receives constructed operator modules and exposes only
  registered configuration/profile ids;
- `config/architecture_local_config.crexx` supplies one example operational
  configuration with local generation/embedding routes and an optional hosted
  route represented by `env:OPENAI_API_KEY`;
- `config/profiles/` supplies independent generic and IT-architecture
  profiles; and
- `config/operator_registry.crexx` is the explicit trusted registration point.

There is no API that accepts or loads an executable module path. Identifier
validation rejects relative paths, absolute paths, filenames, and unknown ids.
Registry construction rejects malformed entries, duplicate config/profile ids,
unknown profile/provider/inverse references, and the currently unsupported
multi-process or multi-in-flight worker scope.

Configuration construction is side-effect free. It imports no provider,
SQLite, native-RAG, or system module. Secret objects retain only an environment
variable name; validation diagnostics and the selection projection never
contain a secret value.

## Focused Proof

CTest `p2_02_config_contract` compiles the model, config, profile, registry,
operator modules, and consumer in optimized and non-optimized modes, then runs
both VMs. All four cells produced the exact success contract:

```text
P2_02_OK cell=<cell> levelg=1 configs=1 profiles=2 env_refs=1 arbitrary_paths=0 secret_values=0 provider_calls=0 source_reads=0 library_writes=0
```

The matrix covers valid typed selection, independent profiles, provider roles,
symbolic environment references, projection bounds, invalid/unknown ids,
relative/absolute/module-path denial, literal-secret denial and redacted
diagnostics, worker limits, unknown provider/profile/inverse references, and
duplicate config/profile registration.

The final resource-measured focused run passed in 18.85 seconds with 134,736
KiB maximum RSS for the complete compile/assemble/four-runtime CTest process.
The retained CMake report contains all compiler and runtime output and scans
clean for the injected secret marker.

## Remaining Limits

- Provider objects describe supported routes; execution remains behind the
  accepted Phase-1B contract and later product wiring.
- The configuration projection is in-memory and non-secret. Schema-backed job
  snapshots, hashes, and durable reproduction metadata remain P2-03/P2-10.
- Only one process and one in-flight item are currently accepted because that
  is the qualified worker boundary.
- The example is operator code, not a public CLI parser or dynamic loader.
- CRI-15 and CRI-16 continue to withhold Linux timeout and industrial
  high-throughput HTTP transport approval.

`P2-03` is next and remains pending. No later Phase-2 item is implied complete
or active by this result.
