# P3R-02 through P3R-05A — Product Ingestion Processor

Status: accepted permanent macOS Gate-3R regression evidence, updated
2026-08-25. This is not Linux qualification, cutover, or release evidence.

The enduring Level-G product now:

- persists schema-v4 `crexx-rag.work-input/1` envelopes for extraction and
  embedding items, including exact source/span/config/profile/provider and
  item-reservation bindings;
- maps configured Gemini requests and validated results through
  `ragapplicationprovider`, behind the existing `.ragworkprovider` contract;
- dispatches public `worker run --once|--follow` to `ragwork` as
  `application-ingestion-v1`;
- promotes candidates and validates typed proposals before graph mutation;
- stores dimension-checked embeddings, publishes the exact immutable `.rxvec`
  generation after the filtered job completes, and reconciles the durable job;
- emits sanitized `plain` or human-only `ansi` progress on stderr while keeping
  JSON/NDJSON stdout stable; human terminal commands select ANSI/plain by
  default and machine callers remain explicit.

`p3r_02_gemini_ingestion` builds the native `crexx-rag` product and runs two
fresh libraries through a deterministic four-request Gemini loopback. The
canonical machine path and the human `init`/guided `ingest`/short `query` path
each perform one structured extraction and one 768-dimensional embedding,
produce an accepted directional claim/support, complete with two configured
worker processes, and retrieve the exact UTF-8 citation. The test also covers
automatic local configuration/library/profile selection, concise human output,
clean canonical `library verify`, sanitized progress, exact request count and
credential-value absence. It also proves that unchanged replay is a successful
zero-job/zero-worker/zero-call result and that a failed child process produces a
non-empty controller error. The concurrent run verifies that any configured
in-flight reservation set fits the immutable job budget before provider work
begins.

The generic transport uses a bounded synchronous connection per attempt. This
is required because a native-bearing cREXX image cannot currently seed attached
bytecode tasks with native RXPA providers (CRI-17). Application workers remain
independent OS processes, each with its own SQLite connection.
