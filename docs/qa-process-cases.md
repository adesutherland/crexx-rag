# Operator process acceptance cases

These cases define observable outcomes, including interruption and recovery.
They are for disposable libraries and deterministic providers. They are not
instructions to experiment on an authoritative library. See the
[coverage review](reliability-coverage-review.md) for blockers and exact build
evidence; a case is qualified only for the boundaries its test actually reaches.

For every case retain the candidate/configuration identities, initial library
census, request identities, event/attempt ledger, final census and public
command results. Compare source bytes, embedding BLOBs and memberships in both
directions, not just row counts. A valid JSON response or a zero controller exit
does not establish successful work.

| Case | Process and deliberate interruption | Required result and recovery | Current evidence / missing boundary |
| --- | --- | --- | --- |
| P01: unchanged ingestion | Ingest and verify a corpus. Change only a provider policy or operational setting through a reviewed config plan. Submit the unchanged corpus again. | Identical no-op; no provider calls, queued items, source changes or embedding unlinking. Existing queries remain valid. | Configuration contract and exact full-size table preservation exist. Repeat with active/paused work and every interpretation class before broad configuration qualification. |
| P02: overlapping useful work | Two native workers process independent chunks. Hold the first provider response until the second request arrives, then release both. Repeat with durable resolutions in bounded dispatch waves. | Exact graph, source, embedding and decision counts; each item accounted once; both workers did actual work; no failed or unfinished items or outstanding reservations; manifest and repositories verify. | `native_publication`: four chunks/two pairs. `durable_backlog_provider`: 40 resolutions/20 pairs with 10-item waves. Mixed extraction/lifecycle/readers and multi-hour soak remain open. |
| P03: failure after a partial batch has been staged | Return a valid extraction, then reject the first claim INSERT after mentions have been staged. | Whole extraction rolls back; source capture and independently completed embedding remain; paid usage remains recorded; item is visibly failed. There must be no published mention/concept prefix. | Native injected SQL failure fails on pinned baseline and passes on repaired batch path. The older single-proposal path still needs this case. |
| P04: cancellation during an admitted call | Claim and reserve work, request cancellation before the admitted provider returns, then deliver the result and usage. | No result publication; one accounted call; no open reservation; attempt/item/job reach cancellation with inspectable usage. A retry must not be implied by cancellation. | Deterministic worker/API interleaving reproduced missing accounting and reservation leakage. Repair qualification is recorded in the coverage review. Actual busy native process cancellation and an expired/reassigned lease are separate gates. |
| P05: crash after durable receipt | Admit one call, persist its response and usage, kill the worker before publication, restart through public worker commands. | Recover that response, revalidate its inputs/fence, publish once or retain an explicit stale/rejected outcome. No second external call for the same recovered receipt. | Public Codex completed-turn crash case and resolution settlement/lease/window cases exist. General Gemini extraction/embedding replay is not implemented/proved. |
| P06: missing projection after terminal work | Complete work, stop the provider fixture, remove the manifest, diagnose, recover from SQLite, verify and query evidence. | Diagnosis explicitly reports missing projection. Provider-free recovery restores alignment and the original compatible index. Source evidence is queryable and usage is unchanged. | `native_publication` runs this sequence after both successful concurrent work and a terminal extraction failure. Active-job and crash-between-commit/rename boundaries remain open. |
| P07: backup, restore and use | After successful or failed terminal work, back up into a new directory, restore into another new directory, verify and query the restored library. | Restored evidence and vector BLOBs/memberships match; history and call accounting survive; no provider call needed to make the restored library usable. | Public native sequence exists. Backup during writers and interrupted/corrupt/full-destination cases remain open. |
| P08: rejected rollback | Stage a later generation, inject a failure in the rollback pointer UPDATE, request rollback, then remove the fault and retry. | Rejected rollback leaves SQLite, FTS and the old manifest aligned. Successful retry moves to the requested ancestor and verifies. | `publication` reproduces the original file-before-SQL ordering defect and tests the repair on both VMs. This is a store API test, not an exposed CLI rollback command. |
| P09: unfinished split/merge | Create successors and child connection questions; leave one connection unresolved; interrupt/resume; migrate remaining evidence; admit retirement only after the impact census is empty. | Parent and original evidence stay addressable; unresolved work survives; no premature retirement; claim direction and individual supports remain intact; no repeatedly charged unchanged question. | Both-VM durable backlog/lifecycle cases exist. Concurrent lifecycle edits with extraction/readers and process death during fan-out remain open. |
| P10: last available resource unit | Two workers request the final call/token/cost/turn allowance; repeat at the deadline, with a slow or failed provider and cancellation. | Admission respects one shared window, releases unused reservations, records actual usage, admits no unapproved call and gives a truthful stop reason. A new window cannot silently reset a previous approved aggregate ceiling. | Reservation/admission/window tests exist. The simultaneous last-unit and busy crash/cancel matrix remains open. |
| P11: late or excessive usage receipt | A provider result returns after lease expiry/reassignment, or reports usage above its reservation. Deliver it twice. | Original usage is recorded exactly once, with an explicit exception/late state if required. The old worker cannot publish knowledge. Already incurred usage is not discarded to preserve a configured limit. | Code review found settlement rejects these cases before durable accounting. This is an open foundational ledger defect, not closed by the cancellation fix. |
| P12: new embedding representation | Review a changed embedding model/representation on a complete library copy; generate replacements incompletely, interrupt, then complete them. | Existing source/history and old embeddings remain available. Queries retain a complete coherent representation until a complete replacement is atomically published. No automatic corpus reingestion for unrelated changes. | Preservation and rebuild checks cover existing representations; the complete replacement/interruption/query matrix remains open. |

For failures, the operator must be able to answer: what committed; what is
pending, failed, cancelled or uncertain; how much work was externally executed;
what recovery command is valid; whether recovery will make another paid call;
and which published view queries and backups will use. If those answers require
ad hoc repair scripts or guesses from process exit codes, the case is not ready
for unattended operation.
