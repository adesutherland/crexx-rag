# Operator process acceptance cases

These cases define observable outcomes for disposable libraries and deterministic
providers. They are not permission to experiment on an authoritative library.
The [coverage review](reliability-coverage-review.md) records current repairs,
evidence and the remaining release qualification boundary. The previous
incomplete coverage assessment is retained in its linked historical record.

Retain candidate/configuration identities, initial census, request identities,
event/attempt ledger, final census and public command results. Compare source
bytes, embedding BLOBs and memberships in both directions. A successful provider
response or zero controller exit alone does not establish successful work.

| Case | Process and deliberate interruption | Required outcome | Executable evidence and boundary |
| --- | --- | --- | --- |
| P01: unchanged ingestion | Capture a corpus, change operational/provider interpretation policy through a reviewed configuration plan, and ingest unchanged observations. Also expand a legacy relative folder URI. | Identical no-op; no new calls, jobs, revisions, membership replacement or generation. Genuine byte changes remain detectable. | `configuration_contract`, `publication` legacy-URI case; full Scottish clone no-op plus exact table comparison and provider-free vector retrieval. Legacy relative URI equivalence is proved from the original working directory. |
| P02: overlapping useful work | Hold extraction responses until two workers arrive; query, back up, restore and verify before releasing each pair. Repeat resolution dispatch in 10-item waves. | Exact semantic and ledger counts; two workers do actual work; no unfinished/failed items or reservations; coherent snapshots. | `native_publication`: four chunks/two held pairs with public readers and backup. `durable_backlog_provider`: 40 decisions/20 pairs by default, with an explicit larger offline lane. A multi-hour duration soak remains a release gate. |
| P03: partial staged batch | Reject claim INSERT after mentions have staged; separately reject a single proposal's second candidate promotion. | Whole item publication rolls back, source and separately completed embeddings survive, usage is recorded, item failure is visible. | `native_publication` SQL trigger; `publication` batch and single-proposal assertions on both VMs. |
| P04: cancellation during a call | Cancel while a native provider response is held, then release it. | No result publication; one accounted call, no reservation, cancelled item/job. | `native_interruption` plus both-VM `publication` cancellation interleaving. |
| P05: death after durable receipt | Commit raw extraction/embedding output, inject settlement failure so worker exits, expire lease and restart two workers. Also exercise Codex persisted-turn recovery. | Reuse received output with normal validation and fresh ownership; original attempt owns exactly one usage record; no repeated external call. | `native_receipts`, `codex_application`, `provider_durability`, resolution lease/window cases. New replay jobs are explicitly new work; same-item restart is the generic receipt scope. |
| P05a: death without receipt | Kill a native worker/controller while the provider holds its admitted response, then restart. | Preserve intent as uncertain; pause job; expose dead letter and event; do not automatically retry or invent zero external usage. | `native_interruption` uses registered test PIDs and a FIFO rendezvous. |
| P06: missing or rejected projection | Reject manifest staging after a committed extraction; recover through public worker/vector commands. Also remove a completed manifest. | Committed item stays processed, no duplicate call, SQLite repairs projection, source evidence and vectors remain queryable. | `native_interruption` first-index case; `native_publication` missing-manifest sequence, verification and provider-free query. |
| P07: backup, restore and use | Back up during two active requests and while an independent connection owns an uncommitted graph mutation; restore/query/verify. Abort incomplete backup staging. | Committed snapshot only, preserved evidence/usage/vectors, no published partial backup, no provider needed for restore. | Combined `native_publication`; both-VM `publication` owned-writer snapshot and abort; terminal native backup with exact vector comparison. Generic disk-full/platform filesystem coverage remains a platform qualification gate. |
| P08: rejected rollback | Reject rollback pointer UPDATE; remove fault and retry. | Rejected rollback retains SQLite/FTS/manifest alignment; accepted rollback verifies against requested ancestor. | `publication`, both VMs. This tests the store API, not an exposed rollback CLI. |
| P09: unfinished split/merge | Create successors and follow-up questions, leave evidence unresolved, resume migration and gate retirement on empty impact. | Parent/history remain addressable, no premature retirement, directional supports preserved, unchanged question is not repurchased. | `durable_backlog` and `lifecycle_methodology` both-VM fan-out, interruption-state, cross-window receipt and stale-decision assertions. |
| P10: final resource unit | Two owners reserve the final call/turn allowance; repeat policy checks at token/cost/deadline boundaries. | One shared admission budget, truthful stopping reason, no leaked or double-counted reservation. | `publication` last-call and running-Codex-turn cases; `provider_durability`, `query_policy` and maintenance window ceilings. Network concurrency is separately demonstrated by native pairs. |
| P11: late/excess/duplicate receipt | Return after expiry/reassignment or above reservation, then repeat exact and conflicting receipts. | Record actual usage once with exception; reject conflicting duplicate; old worker cannot publish. | `publication` both VMs, including explicit stale skip/publication rejection and exact counters. |
| P12: replacement vector representation | Start incomplete alternate-profile vectors; attempt publication; query old representation; finish replacement. Remove/corrupt/interrupt derived sidecars and rebuild. | Complete old representation stays usable until complete replacement; SQLite BLOBs/history survive; no new embedding calls for shadow repair. | `ann_methodology` partial-replacement rejection, both representations and old BLOB preservation; existing corruption/rebuild and query gates. |
| P13: extraction during merge | Preserve a migration parent, give its spelling to the active survivor, deliver a stale extracted identity. | Re-resolve under writer ownership, target survivor, retain parent history, or route an explicit unresolved issue; no revival/partial graph. | `durable_backlog` mixes actual merge workflow with stale provider result on both VMs; full Scottish vector probe checks the original incident's active catalogue result. |

For every failure, operators must be able to identify what committed; what is
pending, failed, cancelled or uncertain; recorded external usage; the next valid
recovery action; whether that action can make another call; and which published
view readers and backups use. The expanded bounded matrix does not establish
unrun nightly-duration, hosted or non-macOS release qualification.
