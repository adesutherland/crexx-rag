# CREXX Integration Issues

Status date: 2026-08-22. The current macOS capability-sync replay uses CREXX
`develop` at base revision `6e6f0ea55d38db346bf78b6542635b2354ba2f04`
plus the accepted RXVECTOR candidate, built out of tree and installed only into
the fresh scratch prefix retained in
[`MACOS-RXVECTOR.md`](evidence/2026-08-22-crexx-capability-sync/MACOS-RXVECTOR.md).

All fourteen original Gate-1A CREXX integration requests have an accepted
upstream disposition and an Apple downstream replay. Fresh Linux qualification
opened CRI-15 for the installed socket receive timeout contract, and Phase-1B
provider measurement opened CRI-16 for the installed HTTP capability ceiling.
Neither issue by itself authorizes a product workaround, donation, a CREXX
edit, cutover, or native-v1 retirement. The Gate-1B decision permits separately
bounded capability work to be prepared alongside Phase 2, with an explicit
repository and write boundary required before implementation.

## Remaining seams

CRI-15 and CRI-16 remain open Linux qualification items. The separate macOS
SHA-256 and RXVECTOR capability work is complete. Current macOS evidence
shows that the downstream provider contract works over the replacement typed
HTTP surface, including stable normalized timeout and connection errors, but
does not prove the supported-Linux timeout, TLS, cancellation, sanitizer, or
concurrency gates. Supported Linux ASan/LSan and final cross-platform installed
replay therefore remain explicitly open. The remaining approved Phase-1B work
is complete and Gate 1B has been accepted. Schema v2 and migrations remain
authorized only within the bounded Phase-2 product scope; this parallel
capability stream does not reorder that worklist.

The historical Google timeout remains retained negative evidence. It must not
be reclassified as an `rxhttp` defect, and no hosted credential or call belongs
in the repeatable Gate-1A pipeline. CRI-15 is a separate deterministic Linux
loopback defect and does not reinterpret that hosted canary.

## Policy for this repository

Consume CREXX through an installed CMake package. Do not restore vendored RXPA
headers, generated-header copying, a sister-source fallback, or a normal-prefix
install as an implicit dependency. Keep the CREXX source checkout read-only.
